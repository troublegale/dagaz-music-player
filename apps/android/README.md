# Dagaz Android

Нативный клиент Compose, Android 9+ (minSdk 28, targetSdk 36), пакет
`io.dagaz.player`. Реализованы подключение к серверу, библиотека и поиск,
потоковое и фоновое воспроизведение, очередь, буферизация и повторные подключения.
Поддерживаются оригинал, высокое и низкое качество, общие офлайн-копии треков,
скачивание альбомов и плейлистов. Редактор библиотеки и переключение
между устройствами остаются следующими этапами.

Нужны JDK 21, Android SDK API 36 и подключённый телефон с отладкой по USB.
SDK настраивается через `ANDROID_HOME` или некоммитящийся `local.properties`.
Из корня репозитория:

```powershell
apps/android/gradlew.bat -p apps/android testDebugUnitTest assembleDebug assembleDebugAndroidTest lintDebug
apps/android/run-device.ps1 -Phase Pairing
```

`Pairing` устанавливает основной и тестовый APK, затем проверяет настоящий
Android Keystore и экран подключения. Тест экрана не заменяет уже существующее
личное подключение, включая резервные файлы `.bak` и `.new`: при их наличии
проверка пропускается, а скрипт сообщает о неполной проверке.
Установка использует `--no-streaming`: на проверенном Poco streaming-установка
отклонялась. На телефоне может понадобиться отдельно разрешить USB-установку
для `io.dagaz.player` и `io.dagaz.player.test`.

Для проверки на устройстве используй `run-device.ps1`, который сохраняет вывод
instrumentation в игнорируемом каталоге проверки. `connectedDebugAndroidTest`
через UTP здесь не используем: он уже удалял установленное приложение вместе
с локальными данными подключения и кешем.

Для сквозного теста запусти изолированный RustFS по инструкции
`experiments/storage/run.ps1`, затем:

```powershell
apps/android/run-device.ps1 -Phase RealServer
```

Скрипт поднимает временный Rust-сервер с отдельной SQLite и собственным тестовым
bucket, подключает телефон через `adb reverse`, проверяет привязку/восстановление/
отзыв и завершает сервер. Временный код остаётся в игнорируемом `.superpowers`,
не выводится в лог и удаляется с файлом готовности после завершения fixture.
Тесты используют синтетические данные; личную музыкальную библиотеку не читают.

Сессия целиком, включая origin сервера и ID устройства, шифруется AES-GCM ключом
Android Keystore. JSON лежит в `noBackupFilesDir`, заменяется через AtomicFile;
резервное копирование и перенос данных приложения отключены. Повреждение файла
или отсутствие ключа требуют новой привязки. Keystore и сеть работают вне UI.

В обычной сборке разрешён HTTPS. HTTP доступен только в debug и только для
`127.0.0.1`/`::1`. Редиректы отключены; токен прикрепляется только к origin своей
сессии. Wire-модели проверяются общими JSON-примерами из `fixtures/contract`.

`assembleRelease` создаёт неподписанный APK: подпись и распространение относятся
к выпуску. Результаты проверки устройства: [Android client validation](../../docs/validation/android-client.md).

Этап A2 добавляет библиотеку, поиск, альбомы/исполнителей и
MediaSessionService с очередью, перемоткой, повтором и перемешиванием.
Проверка на подключённом телефоне: `apps/android/run-device.ps1 -Phase Playback`.
Она использует только синтетические WAV/MP3/FLAC и временную тестовую привязку;
при наличии личной привязки тесты пропускаются, а скрипт не считает такой прогон
успешным. Высокое/низкое качество обслуживается задачами S6; неготовое качество
показывает подготовку. Исходный MP3 переиспользуется без отдельной копии кеша,
если его битрейт уже не выше выбранного. Создание/редактирование плейлистов
и перенос воспроизведения между устройствами ещё не готовы.

`apps/android/run-device.ps1 -Phase ServerPlayback` поднимает изолированный
Rust-сервер/RustFS, импортирует синтетический 30-секундный WAV и MP3, готовит
качества настоящим FFmpeg и проверяет их через продуктовый MediaSessionService
на телефоне. Как и `RealServer`, этот режим требует подключённый ADB и тестовый
RustFS; временный код хранится только в игнорируемом файле и удаляется fixture.

Для ручных проверок используются отдельные режимы (телефон разблокирован в начале):

```powershell
apps/android/run-device.ps1 -Phase ScreenLock
apps/android/run-device.ps1 -Phase Headset
```

`ScreenLock`: после появления тона выключи экран физической кнопкой и оставь
выключенным до остановки звука (15 секунд после выключения). Тест ждёт нажатие
до минуты и проверяет продвижение позиции и состояние единственного плеера.
`Headset`: заранее подключи Bluetooth-наушники; после появления тона отключи их.
Тест проверяет реальное исчезновение устройства и паузу без перехода на динамик.
Эти режимы не нажимают кнопки телефона и не подменяют системные события.

## Скачивание и офлайн

Кнопка «Скачать» доступна у трека, альбома и плейлиста; качество скачивания
выбирается отдельно от потокового. «Скачанное» показывает фактическое качество,
незавершённую загрузку, обновление файла и удаление на сервере. Нажатие на
сохранённую подборку воспроизводит её снимок с исходным порядком и повторами.
Удаление одной подборки сохраняет файлы, на которые ссылаются остальные.
Обновление снимка/файла и изменение качества выполняются явно; изменение
качества затрагивает общую копию во всех подборках после успешной проверки.

Room хранит каталог, состав плейлистов, курсор синхронизации, снимки и ссылки
на файлы. Каталог и membership публикуются транзакционно после получения всех
страниц. Привязка локального каталога к адресу личного сервера позволяет
сохранить скачанное при новой авторизации на том же сервере; другой адрес
получает отдельный каталог. Для будущих нескольких библиотек на одном адресе
потребуется отдельный идентификатор библиотеки.

Media3 DownloadService/DownloadManager используют один постоянный кеш без LRU;
потоковый кеш остаётся отдельным и ограничен 1 ГиБ. Ключ включает канонический
адрес трека, ревизию, фактическое качество и SHA-256. Готовность публикуется
только после проверки полной длины и хеша чтением без сети. До этого старая
готовая копия сохраняется. Обрывы повторяются с задержками 1–30 секунд и jitter;
ошибки доступа, версии и записи на диск завершают попытку с явным статусом.
WorkManager выполняет ограниченную четырьмя минутами подготовку манифеста,
аудиопередачей управляет Media3. На Android 15+ действует [системный лимит
фонового dataSync](https://developer.android.com/develop/background-work/services/fgs/timeout):
при timeout сервис ставит скачивания на паузу.

Дополнительные зависимости закреплены: Room 2.8.5, WorkManager 2.11.2;
Kapt использует ту же Kotlin 2.2.20, Media3 остаётся 1.8.0.

```powershell
apps/android/run-device.ps1 -Phase Offline
apps/android/run-device.ps1 -Phase ServerOffline
```

`Offline` проверяет общий файл, ретраи и Range, неуспешную замену, совпадающий
URL с новым хешем, снимки/повторы, синхронизацию и общий индекс фонового сервиса.
`ServerOffline` скачивает синтетический альбом и плейлист через настоящий Rust/
RustFS, разрывает только их USB-туннель и запускает отдельный instrumentation
процесс. Он проверяет холодное офлайн-воспроизведение, поиск и сохранённые обложки.
Личная привязка не заменяется; тестовые коды и маркеры удаляются после проверки.

Длительные метро/Doze-прогоны, заполнение физического диска, производительность
большого каталога и очистка неиспользуемых локальных обложек ещё не проверены
или не завершены; это контрольные точки перед выпуском.
